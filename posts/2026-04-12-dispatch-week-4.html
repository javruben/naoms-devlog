Every change to your data now goes through one signed, audited path — no side doors.

Process Dispatch free April 12, 2026·5 min read·meta
TL;DR Here's what shipped for you this week, mostly under the floor: every change to your data now flows through a single signed, audited path with no side doors, setup now drives the real onboarding instead of a shortcut, and our checker learned to fix its own findings. Honest about what's still open, and the one feature we cancelled — correctly.

The week the pixels took a break and the plumbing got serious. If Week 3 was the identity-verification era, Week 4 is the governance-and-chain-discipline era: governance gets pulled out of the command line and folded into the policy engine, every write to the ledger gets funnelled through a single audited path, and a critic sweep spends days paying down the import-graph wreckage left by a month of big rename refactors. Almost no new UI — lots of load-bearing internals.

Shipped (verified on the main branch)

Each of these is verified against the work item's own records as of 2026-06-12 — not assumed.

  • Improved — Every change to your data now goes through one signed, audited path, so nothing can quietly write around the record. We funnelled the old direct-write shortcut into a single audited path across the whole codebase — enough of a change to break 130 import sites at once, the kind of pain you pay once to never have two ways to write again. (One door in.)
  • Improved — Our own checker can now fix many of the problems it finds. A three-tier autofix engine: mechanical edits, a local model for the trickier rules, and a per-file safety check so a bad machine edit can't poison the run. (The checker learned to fix itself.)
  • Fixed — Queries can no longer quietly claim success when they failed. We added error checks to all thirty-five database-query sites that were missing them — a whole class of silent "it worked" that wasn't.
  • Improved — Hardened the integrity of your chain and your vault.
  • Fixed — Closed five critical and six high-severity gaps in re-encryption. An earlier review had found protections marked "done" that were in fact dead code, disabled, or silently violated; this work closed them — device-key persistence, print-validation hardening, and more.
  • Improved — Setting up an account now drives the real onboarding, not a shortcut. The dev/test founder reset runs the genuine onboarding flow, and the standalone governance command was removed — governance folds into the policy engine.
  • New — Agents can now create and update roadmap work the audited way (partial — see below), with an atomic ID counter and projection into the queryable graph. A companion cleanup item reached celebration.
  • Improved — Facilitator policy update (shipped — closed later, 04-21).

Broke & fixed (honest)

  • A frozen object took down every dynamic feature. Freezing the feature registry — a "harmless" hardening — froze it before the dynamic modules could register into it. Result: consent, vault, contacts, hives, and all other UI tabs silently failed to load; only 6 of 30-plus features survived. Reverted same day (04-10). Full confession published this week.
  • A top-severity injection bug hiding in the error display. The critic sweep found the client rendering raw error text as live markup — error messages from failed requests could carry injection. Fixed by building the elements explicitly and rendering the text as text (04-11). Lesson, not recipe.
  • A comment that killed the daemon. A stray comment terminator inside a doc comment's path string ended the comment early and broke daemon boot (04-12).
  • 130 broken imports after the write-path migration, and 19 micro-app files with syntax errors from the repo sweep — both fixed. The pattern of the week: rename refactors break import graphs, and the fix commits (over 1,400 of them this window) are the cost of cleaning up behind them.

Concept of the week — "Why funnel every write through one path?"

A chain is an append-only log of signed events; the graph everyone queries is a projection of that log. If code can write the graph two ways — a raw direct write here, an audited append there — then half your writes skip the signing, the audit trail, and the projection step that keeps the queryable view honest. You end up with state nobody can prove the provenance of. Funnelling every write through one audited path means every change to the world is signed, audited, and projected the same way — so the queryable graph is always a faithful projection of an accountable log, with no side doors. The 130 broken imports were the price of bricking the side doors shut. Worth it.
