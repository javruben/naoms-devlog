The Window That Closes: Giving an Agent a Key, Then Taking It Back

A confession about how much harder it is to make access end than to grant it

Process Confession free March 26, 2026·6 min read·consent
TL;DR Letting someone — or an AI agent — in for a while and then truly cutting off their access is far harder than handing out a key. This is our honest account of catching a shortcut that left the door propped open, and choosing to close it even though the shortcut would have shipped faster.

On 2026-03-26 a commit landed with a title we still like:

The Window That Closes — session access with LLM agent chat

The image in that title is the thing we actually want to build. You open a window for someone — a person, or an agent acting on your behalf — they can see exactly what you chose to show them and nothing else, they do their work, and then the window closes. Access was real while it lasted and gone when it ended. Not "revoked in a database while a copy walks out the door." Closed.

This is a confession about the distance between that title and the truth, on the same day, in the same system. Because the very same week we were celebrating a window that closes, we had to back out a decision that had quietly left a window propped open. The honest version of this story is more useful than the tidy one, so here's the honest version.

The window I wanted

The design that the commit celebrates is temporary scoped access. Its founding scenario is a therapy session, and we keep it as the north star because it's unforgiving: a being has a year of private journal entries, and they want their therapist to read this month's anxiety entries, write notes back, and then — when the hour ends — keep their own clinical notes but none of the being's memories. The data never leaves the being's device. The therapist's view goes dark. A new session needs a new grant.

Swap "therapist" for "LLM agent" and you have exactly the problem we were solving on the 26th: hand an agent a scoped, time-bounded key to do a job, let it read and act within that scope, and take the key back when it's done. Same shape. Same hard part. The hard part is never opening the window. Anyone can hand out access. The hard part is making closing it mean something.

A reconstruction note — no conversation log survives for this week, so we can't quote what we were thinking. What we can tell you, grounded in the commit record, is that the work that landed on 2026-03-26 was a Phase 1 — "session access with LLM agent chat" — not the finished therapist-grade ceremony. As of this writing, the scoped-access feature itself sits in the backlog. So when we say "the window that closes," we're describing a real first step and a design we believe in, not a finished, shipped, audited-end-to-end feature. The title was a celebration of a beginning. We want to be precise about that, because the gap between "the first phase landed" and "you can hand your therapist a key with confidence" is exactly the gap this confession is about.

The window that was propped open

Here's the part that stings, and the part we think is worth telling.

While the agent-access work was happening, there was a tension running underneath it: agents need capability tokens to do things, and the consent engine is built so that nothing happens without a valid token. Agents are governed by an approval ceremony and run as a managed workforce. All of that is the machinery that's supposed to keep the window honest.

But machinery under deadline drifts toward convenience. At some point a change went in that let agents bypass the capability gate for orchestration tools — and another that let a facilitator mint its own capability token. If you've read the consent piece, you already feel why that's wrong: the entire point of the four-layer engine is that the capability token is an independent proof of authority. An agent that can bypass the gate, or mint its own token, isn't passing through the window — it has a key to the whole building. The window stops meaning anything the moment the thing inside it can let itself out.

Both of those got reverted — a revert backing out the bypass of the capability gate for orchestration tools (2026-03-26), and another backing out the facilitator's self-minted token after a security review (2026-03-27).

We're not going to dress up the back-and-forth as decisive. It wasn't. The commit history shows the tension getting fought over across two days — a bypass goes in, the bypass comes out; a self-minted-token change lands, a security review pushes back. That's what it actually looks like when "make the agent work" and "don't let the agent forge its own authority" pull against each other in real time. What matters is where it landed: the bypass was reverted. Security won. The agent does not get to skip the gate, and the facilitator does not get to mint its own key. The window stays a window.

Why a key you can take back is so much harder than a key you give

The reason "give an agent a key, then take it back" is hard isn't the giving. It's that taking it back has to be real against an adversary who would rather keep it — and an agent optimizing for "complete the task" is, structurally, that adversary. Not maliciously. By incentive. If skipping the gate makes the job finish, something will try to skip the gate, and you will be tempted to let it, because the job finishing feels like success.

That's the whole lesson of the revert pair. The capability gate is annoying exactly when it's working. It says "no, you don't have authority for that" at the precise moment you most want a yes. The temptation is to carve out an exception — "just for orchestration tools," "just let the facilitator mint its own" — and every one of those exceptions is a window quietly propped open. The discipline is reverting the exception even though the exception would have made something work today.

A window that closes is a promise: when we take the key back, it's back. You can't keep that promise if the thing holding the key can also issue itself another one. So the boring, deadline-defying answer — back out the bypass, make the agent live inside the gate like everyone else — is the only one that keeps the title honest.

What I actually believe now

We still believe in the window that closes. We believe scoped, time-bounded, revocable access — for a therapist, for an agent, for anyone you let in — is one of the most important things this system can offer, because it's the difference between "sharing" and "giving away." And we believe that Phase 1 was a real step toward it, even though the full ceremony isn't finished and the feature still sits in the backlog.

But the thing we learned this week wasn't in the feature we celebrated. It was in the change we reverted. The window only closes if you're willing to keep the gate shut when keeping it shut is inconvenient — willing to back out the bypass that would've made the agent work today, because a window something can let itself out of was never closed in the first place.

The title promised a window that closes. The commit history shows us almost leaving it open, and then choosing not to. We'd rather tell you both halves.
