Four things changed this week

Nothing was published in these seven days, so this week is read from its own record rather than from companion articles.

1

Bridge accounts got somewhere safe to keep their credentials

Slack and Discord had no credential-sealing path at all. Both now have one, WhatsApp and Signal seal their linked-device credentials into the vault, and the plaintext session directories are wiped when the daemon stops.

2

The phone could not repair itself, because zero looked like nothing

A valid database handle whose value was zero was rejected by a guard written to catch unset handles. No mobile device could complete a repair. The whole class is now closed behind one shared check.

3

A closed group can be asked to let you in

A closed group used to look identical to one that did not exist. It now shows "Request to Join", stewards get a list of requests they can approve, and an invitation says who sent it.

4

Money arriving says who it came from

A received settlement showed up in the wallet with no payer attached. Both halves now name the other party — "received from", "sent to, paid" — and the live feed carries the amount and memo.

Bridge accounts finally have somewhere to keep a credential

The feature: connecting an outside chat account — Slack, Discord, WhatsApp, Signal — so its messages arrive here alongside everything else.

Before: Slack and Discord had no credential-sealing path whatsoever. WhatsApp and Signal produced linked-device credentials that lived in a plaintext directory on disk. Signal was not even registered as an adapter, so the code that starts a link ceremony had nothing to reach.

Now: all four have an in-app ceremony, the credentials are sealed into the vault, and the plaintext session directories are wiped when the daemon stops.

A credential in a plaintext directory is not stored. It is left. The distinction matters because the code around it looks finished either way — there is a file, it is read back, the feature works. Nothing fails until somebody copies a laptop backup. This is the failure mode that does not announce itself in any test, because the test asserts the credential round trips, and it does.

Six silent catches got a voice. The WhatsApp and Signal link path had six places that swallowed an error and continued. A link failure therefore looked identical to a link that had not been attempted. Each now says what happened. A silent catch is worse than a crash: a crash tells you where to look.

History never loaded. Connecting a bridged account brought the account across but not its past. The synchronisation that pulls existing history on connect was written and was never armed, so every reconnection produced an account with an empty backlog. Nobody reported it as broken, because an empty conversation looks exactly like a new one.

Two files were split because size is a defect. The Signal adapter went from 1,702 lines to 616 and the route table from 1,638 to 704. Splitting them surfaced three genuine test failures that had been passing inside the larger files. A file big enough to hide a bug is big enough to hide several, and the ones it hides are the ones no reviewer has read to the bottom of.

One ceremony, then five. The onboarding assistant could only connect one of the six services, because only that one had been exposed as an operation it could call. The other five existed and worked — they were simply unreachable from the place people start. Building a capability and wiring it to the surface people actually touch are two pieces of work, and the second is easy to believe you have already done.

One call reported success having done nothing. Connecting WhatsApp by scanning a code returned "authentication flow started" without starting one. The caller had no way to tell that apart from a flow that started and was never completed, so the interface waited for something that was never coming. Four built-in connectors were also pointing at files that were not the real ones. A function that returns a success value is making a claim, and a claim nothing checks is a guess with good manners.

Messaging bridges — 212 changes this week, the largest area.

The phone that could never heal, because zero looked like nothing

The feature: a device repairing its own copy of your data when it finds it has fallen behind.

Before: it never ran on a phone. A guard meant to reject an unset database handle also rejected a perfectly valid handle whose value happened to be zero.

Now: the check distinguishes the two, and the same predicate is shared by every site that needs it rather than rewritten at each.

Why zero is the value that catches you. In JavaScript, the large-integer zero — 0n — is one of seven values that count as false in a plain truthiness test. This is not obscure; it is documented in every reference on the language, alongside 0, "" and NaN. Anyone who has written JavaScript for a year knows it.

Knowing the rule did not prevent the bug, and that is the interesting part. The guard was not written by someone unaware that zero is falsy. It was written where the handle was never zero, and it was correct there. The value became zero later, at a boundary — crossing from the native layer into the JavaScript engine the mobile client runs. The code that changed and the code that broke were in different files, different languages, and different years.

What made it expensive was the shape of the failure, not the size of it. Nothing crashed. No error was logged. The repair simply never started, on one platform, in a path that only runs when a device is already behind. The symptom was an absence, and absences do not appear in a stack trace. That is why the fix closes the class — a shared predicate every site now calls — rather than the two sites that were found.

A guard's correctness is a property of the boundary it sits on, not of the line it occupies. Move the same line to a place where the value can legitimately be zero and it becomes a bug, silently, with no edit.

It was not confined to one place. The same misreading turned up in the contact store, where a live handle of zero was again treated as "no database". Two components, written at different times by different people, made the same wrong assumption about the same value — which is the signature of a fault in a shared boundary rather than in either caller.

The fix is a predicate, not two edits. Both sites now call one shared check that distinguishes an unset handle from a zero-valued one. That is deliberately more work than fixing the two occurrences: the third occurrence has not been written yet, and a shared predicate is the only version of this fix that covers it.

What else crossed that boundary this week. Real group-messaging cryptography now runs under the mobile engine, replacing a stand-in, and a simulated selective-disclosure scheme was replaced by the real implementation. Both are the same kind of change as the zero-handle fix — a place where the mobile path had been running something that resembled the desktop behaviour rather than being it.

Zero is a value, not an absence

A database handle of zero was rejected by a guard checking for a missing handle, and no phone could repair itself. That zero is falsy is thoroughly documented and widely known. The lesson is not the rule — it is that a correct guard becomes wrong when the value crossing it changes, without anyone editing the guard. Ask what a check does when the legitimate value is zero.

A credential in a plaintext directory is not stored

Four bridge integrations produced credentials and left them on disk, two of them with no sealing path at all. Every test passed, because the credential round-tripped. A test that proves data comes back proves nothing about where it rested. Storage has a location, and the location is part of the behaviour.

Settle on stillness, not on a count

The photo library's recorded walkthrough waited until a target number of cards appeared, then rolled. On a slower machine more cards were still arriving. Waiting for the library to stop changing is right where waiting for a number is wrong. Mutation-based settle detection is established practice — Remotion's frame-deterministic model and MutationObserver signalling in browser automation both do it. The part worth adding: a plateau needs a longer observation window than a target does, because "nothing happened yet" and "nothing will happen" look the same for a moment.

A bound must count the thing its name promises

A limit on how deep a chain of deferred work could recurse was counting how many items were queued. Under load the queue grew for ordinary reasons and the limit fired on work that was not recursive at all. A bound whose name and measurement disagree fails in the direction that looks like the thing it was meant to prevent — which is why it survives review.

An architectural rule nobody can forget is worth a check

"Subscribe, don't poll" was a convention every reviewer agreed with and some code ignored, because a poll loop is the easier thing to write and reads perfectly well in isolation. It is now a repository check that refuses one. A convention that only exists in reviewers' heads is enforced at the rate reviewers remember it. Where the wrong thing is locally easier, the rule needs a machine behind it.

What would prove this week wrong

Four things this report claims that are only half-proven.

  • The zero-handle class is closed, not the bug. A shared predicate now covers every site found. Whether it covers every site that exists is a different claim, and only a device that was previously stuck and now heals proves it.

  • Sealed does not mean audited. The bridge credentials moved from a plaintext directory into the vault and the directory is wiped on shutdown. Nobody outside this project has looked at that path.

  • A busy week with nothing published is a reporting gap, not a quiet week. 2,328 commits produced no article. That is the failure this dispatch exists to correct, and it will recur unless something notices the absence.

  • Real cryptography replaced two simulations this week. Selective disclosure and mobile group messaging both moved from stand-ins to the real implementations. Neither has been exercised at scale, and a scheme that works in a test is not the same as one that holds under real traffic.
