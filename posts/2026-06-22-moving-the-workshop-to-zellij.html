Moving the Workshop to Zellij

A home for a hundred autonomous agents is easy to draw and hard to keep honest. This is the confession of four bugs that each came from the workshop quietly lying about its own state.

Process Confession free June 22, 2026·8 min read·craft
TL;DR We build NAOMS with a large number of autonomous AI sessions running at once, often more than a hundred. They have to live somewhere a human can see, steer, and recover. We moved that home onto Zellij, a terminal workspace, and then spent weeks fixing the ways the workshop lied to us about its own state: a reconnect that gave up when it should have retried, a list that drew dead desks as live, a refresh that typed into the void and reported success, and a multiplexer that throttled itself under load. This is the honest middle of that build.

Most of what we publish here is about the product. This one is about the workshop, because the workshop is where the honesty axiom gets tested first, before any of it reaches you. We build NAOMS with a large number of autonomous AI sessions running at the same time, frequently more than a hundred. Each one owns a slice of the work. That is the whole engine of the project, and it has a brutally practical problem underneath it: where do a hundred live, busy sessions actually live so that a human can look at the board and trust what it shows?

We moved that home onto Zellij, a terminal workspace that tiles a screen into panes. The picking was the easy part. The hard part — the part worth a confession — is that a workshop for autonomous agents has a failure mode that a workshop for humans does not. A human notices when their tools are lying. An agent does not. If the board says a session is alive when it is dead, an agent will happily route work to a corpse. Every fix below came from the workshop telling us something that was not true, and every one taught the same lesson: at this scale, a tool that guesses cheerfully is worse than one that admits it does not know.

Desks: sessions made of panes

The unit we settled on is the desk — a Zellij session that holds a group of panes, each pane a working agent. Instead of a drift of separate terminal windows you lose the moment there are more than a few, the fleet becomes a board you can read at a glance: this desk is the quartermaster's fleet ops, that one is a feature crew, these panes are the agents inside it. A handful of verbs operate on desks — list them, attach to one, refresh a single pane, recover a whole desk after a reboot.

Drawn on a whiteboard, that is a clean abstraction. The trouble is that every one of those verbs sits on top of a real multiplexer process that can crash, get rebooted, kick its clients, or throttle itself — and the abstraction is only as honest as its behavior in exactly those moments. So this is the story of the moments.

The list that drew corpses as living

Start with the most dangerous lie, because it is the quietest. After a host reboot, every Zellij session comes back as an EXITED shell — present in the session list, attachable to resurrect, but not running. Ask such a session for its panes and the query fails outright.

Our desk list had a reasonable-looking line of code for that failure: when the pane query returned nothing, it returned null and moved on. The intent was defensive — "I could not check, so I will not make claims." But the renderer read null as no problem found and printed every member of the desk with no annotation at all, indistinguishable from a live pane. After a reboot, the board showed thirteen dead desks as a wall of healthy green.

That is the failure mode that matters most for an autonomous fleet, because no human is reading every line. An agent asks "is this desk up?", the board says yes, and work flows into a session that no longer exists.

The fix was to stop conflating two different unknowns. We added a check that parses the session list directly and reads the EXITED marker as a positive fact: this session is confirmed not running. Now there are three states, not two. If the pane query fails and the session is confirmed dead, the desk is tagged [DOWN — zellij session not running] and every pane inside it is flagged missing. If the pane query fails but Zellij itself is unreachable, the desk stays null — genuinely unknown, and labeled as such, never as a false DOWN. The distinction between "I know it is dead" and "I cannot tell" is the entire fix. Verified against the live fleet: the running desk rendered clean, and all thirteen exited desks flagged DOWN.

The refresh that typed into the void

The second lie was louder, and it came from the owner. He ran desk refresh on a pane to restart the agent inside it, and, in his words, "absolutely nothing happened" — except the command cheerfully printed relaunched.

Here is what the old refresh actually did: it typed the resume command into the pane, as if a human were at the keyboard. If the pane held a live agent, that agent swallowed the keystrokes as ordinary input and did nothing with them. The keystrokes went into the void, and the command reported success because, as far as it knew, it had sent the bytes. Worse, the layer underneath it had collapsed the multiplexer's error output down to a bare true/false, so even when an operation genuinely failed, the actual error was discarded before anyone could read it.

The rebuild changed the mechanism entirely. desk refresh now closes the pane and reopens it through the same wrapped placement path a fresh launch uses — no typing into a possibly-live session, ever. But closing a pane raises a sharper hazard: if you close a session you cannot reopen, you have destroyed an agent's running conversation. So the order of operations is deliberately paranoid. It resolves how to resume the session before closing anything. If the pane was spawned without a stored resume handle, it discovers the live session by finding the newest transcript whose working directory matches. And if no resumable identity can be found at all, it refuses to close the pane and fails loudly — the one thing it will not do is close a door it cannot reopen.

The verification for this one is the part we are proudest of, because it is the opposite of typing into the void and hoping. There is an integration test that spins up a real detached Zellij 0.44.3 server on a throwaway, isolated session — never the real fleet, never a production desk — and drives the close-and-reopen through it, asserting by reading the actual rendered screen that the pane came back resumed at the same slot. The workshop now has a test that watches the workshop work.

The reconnect that gave up too early

The third lie was a matter of degree, and it is the most subtle. Under heavy load, the Zellij server kicks its attached clients — roughly once a minute when the machine is busy. So we built an attach verb that reconnects: attach to a desk in the foreground, and when the server drops you, wait and re-attach instead of silently leaving you detached.

The decision of whether to reconnect is a small loop, and getting it right turned out to be the whole game. The trap is that a clean detach and a server kick look identical — both exit cleanly under load, so the loop cannot tell "the human left" from "the server threw me out." The honest decision is therefore narrow:

    A[client disconnects from desk] --> B{is the desk
still alive?}
    B -- "no, server exited" --> C[STOP
nothing to reconnect to]
    B -- "yes — clean exit and a kick

    F -. "Ctrl-C during the wait" .-> G[STOP
the human's deliberate exit]

The first version had a bug that looked harmless and was not. It treated a clean exit code as the user left on purpose and stopped the loop. That is correct when a human deliberately detaches. But under load, the server's kick also exits cleanly — the same exit code for "I am done here" and "the server threw me out." So the loop did the polite thing and gave up at the exact moment it was supposed to fight, leaving the owner staring at a dead terminal while the desk ran on without a window.

The fix has two halves, and the second is the real one. The shallow half: stop treating a clean exit as a reason to quit. Only one condition ends the loop on its own — the desk is actually gone. Everything else retries; a deliberate Ctrl-C during the wait is the human's way out.

The deep half was asking why the server was kicking clients in the first place. The root cause was a Zellij feature that is on by default: session serialization, which writes the full state of a session to disk every time a pane's output changes. With many active agent panes all producing output at once, that is relentless disk I/O, and it delays the server's own client-ping loop enough to drop the clients it is supposed to be holding. The workshop was throttling itself by trying too hard to remember everything. So at desk creation we now write a minimal Zellij config — serialization off, a bounded scroll buffer — and pass it in. The reconnect loop is the seatbelt; turning off serialization is fixing the road.

Why we are confessing about a terminal multiplexer

Because the unglamorous infrastructure is where reliability actually lives, and because the pattern across all four bugs is the one thing we most want to be true about NAOMS as a whole. Every fix was the same move: take a place where the tool was guessing optimistically and replace the guess with a state that is either verified or honestly marked unknown. A null that meant "fine" became a DOWN that means dead and a null that means I cannot tell. A "relaunched" that meant "I sent some keystrokes" became a close-and-reopen that refuses to act when it cannot guarantee the outcome. A reconnect that assumed a clean exit was intentional learned the difference between leaving and being thrown out.

This is the same honesty axiom we hold the wallet to — no unmarked state, no reassuring fiction — applied to the scaffolding instead of the product. It is the floor underneath the role that keeps a hundred agents moving: that orchestration is only trustworthy if the board it reads from refuses to lie.

Honestly scoped

None of this is a feature you will ever tap. It is internal tooling, the scaffolding we build with, and we are showing it to you because building in the open means showing the workshop and not only the finished pieces on the shelf.

And it is not done. The move to Zellij is load-bearing and still being hardened — the four fixes above are the ones that broke loudly enough to catch, and we will not pretend there are no others waiting under load we have not hit yet. The interactive parts of the attach-and-reconnect cycle still need a real human at a real terminal and a real server kick to exercise end to end; the unit tests cover the decision, not the full live cycle. The shape is right and the lies we have found are fixed. The honest claim is exactly that, and no more.
