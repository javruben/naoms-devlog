Four things changed this week

One per area, none of them touching the same code. Two are features, one is a measurement we had been reading wrong for weeks, and one is a pair of security gates that had been standing open.

1

Your shared data got real encryption

The re-encryption that protects anything you share is now genuine cryptography rather than a stand-in, and it became the default everywhere on 06-08. It is built on a post-quantum lattice library, and it has not been externally audited.

2

Any package can be filled with production-shaped data

One command pours a real-world-shaped sample dataset into a package, loaded at the lowest layer, so every surface above it fills up the way it would in daily use instead of sitting empty and looking finished.

3

The local model was driving the workflow all along

For weeks the tests said the local model never called a tool, run after run. The dispatch was happening the whole time and our own harness was failing to see it. The rate now reads about 80%, up from about 38%.

4

Two gates that had been standing open got shut

A permission check on shared files was defaulting to allow where it should have defaulted to deny, and a live authorization bypass in group invitations was found and closed, caught by a new automated source check rather than by someone noticing.

The encryption that built cleanly for months without encrypting

The feature: re-encryption — handing someone access to something already encrypted, without anything in the middle having to decrypt it first.

Before: the path existed, ran, and passed its tests, but the transformation underneath it was a placeholder that performed no real cryptography.

Now: a genuine proxy re-encryption backend, built on a post-quantum lattice library, sits under that path and is the default everywhere.

The real backend first landed on 2026-06-06 and became the default two days later, on 06-08 — replacing a placeholder that had been in the tree since April. The placeholder was never a secret, but it was also never a visible defect from outside.

A component that compiles proves nothing about what it computes. The placeholder had the right shape: the right function names, the right arguments, the right return type, and a passing build. Every signal a build system emits was green, because none of those signals asks whether the bytes coming out are actually protected.

That is the ordinary way a stand-in survives for months. Nobody decides to keep it. It simply stops being visible, because the thing that would have made it visible — a test asserting what the cryptography does, rather than that it ran — was never written.

The caveat we are not going to bury

The new backend has not been through an external audit. Cryptography that has not been reviewed by people outside the project is cryptography that has not been reviewed, however modern the lattice library underneath it and however carefully the people who wrote the integration read their own work.

We are shipping it as the default anyway, because the honest comparison is not against an audited backend. It is against a placeholder that protected nothing at all. That comparison is easy; it does not make the audit optional.

The zero was our own instrument, not the model

The feature: the local language model calling a real tool to drive a workflow, rather than describing in prose what it would do.

Before: every test run reported the model had called a tool zero times, run after run, for weeks.

Now: the rate reads about 80%, up from about 38%, after the zero turned out to be a reporting fault rather than a model failure.

The zero was persuasive because it was consistent. A rate that wobbles invites questions; a flat zero reads as a settled fact about the model, and the conclusion it suggests — the model cannot do this — is comfortable, because it puts the problem outside our own code.

It was our code. The daemon was dispatching the call end to end, and writing a real commit for it, while the harness watching the run reported nothing had happened. Two fixes followed: the prompt we had been quietly garbling was repaired, and the model's thinking mode became the default for the model family we run.

What is still open

The rate moved from about 38% to about 80%. That is not solved, and the wider work of seeing what the model is doing while it runs — the thing whose absence let a false zero stand for weeks — is still open.

We are naming the number rather than the improvement because a percentage that has stopped at 80 tells you something a phrase like "much better" does not: one run in five still does not do the thing.

What this means, in plain terms

Most of what lands in a week belongs only to the thing it landed in, and is not worth a general reader's time. A few things transfer. These five were paid for by getting them wrong first, somewhere in this codebase, this week.

A gate's default has to be the safe direction

The permission check on shared files shipped defaulting to allow. It was supposed to deny by default and permit on proof, and in every ordinary test — where proof was present — the two behave identically. The difference only appears when something is missing. Design the failure case, because that is the only case the default is ever consulted for.

Prove your instrument can see a success before you believe a zero

The tool-call rate read zero for weeks. It was not the model refusing; it was our harness failing to observe a dispatch that was demonstrably happening. A consistent zero looks like a strong result and is the reading an instrument gives when it is broken. A measurement that has never once produced a positive result is a claim about your instrument.

A green build says nothing about what the code computes

The re-encryption placeholder had correct names, correct types, and a clean build for months. Everything automated around it was satisfied, because none of those checks asks what came out the other end. When a component's whole value is in the output, test the output — a passing build only proves the shape.

A surface that shows the right things and does none of them is not the feature

The first file browser looked right and was rejected outright as fake: the controls were there, the behaviours behind them were not. The rebuild put real interactions in — inline rename, previews that navigate, a selection total, a folder created in place. A screenshot is evidence of a layout, never of a feature.

Real-shaped data finds what an empty screen hides

Every package can now be loaded with a sample dataset shaped like actual use. Empty surfaces conceal the things volume breaks: ordering, truncation, pagination, what a long name does to a column. Test at the shape and size of real use, because most failures are properties of the data, not the code.

Four claims here that are only half-proven, and what would settle them

Each of these is something this report has shown only partly, and each would read as more finished than it is if you saw only the headline. Each names the gap that remains rather than the task that would close it.

  • The encryption is real and unreviewed. Nobody outside the project has examined it. Until someone has, "genuine cryptography" is a statement about the library we chose, not about the way we used it.
  • We do not know what else our instruments are not seeing. One harness reported a flat zero through weeks of a working mechanism. The fault is fixed; the question of how it went unquestioned for weeks is not.
  • Value cannot move between two devices. Every token operation that works today works in one place. A transfer that needs two devices to agree is the part that has to be proven, and it has not been.
  • Neither the file browser nor the photo surfaces are finished. Both have real behaviour behind real controls now. Neither has been walked end to end by someone who did not build it.
From the workshop

The Map Is Not the Territory

There is a difference between surveying a space and being in it. A top-down view gives you oversight of where things are; presence gives you somewhere to stand. The design NAOMS reaches for is the second — a character in the screen who walks where you point, a companion in a room, rather than a pin on a chart.

The rooms are a metaphor for the context you are in. The same instinct shows up smaller: you don't want to read a friend's long cryptographic key, you want your friend. More screen is not more presence.
