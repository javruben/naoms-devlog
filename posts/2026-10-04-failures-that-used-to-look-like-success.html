Failures that used to look like success

A video that used to be cut into dozens of pieces becomes one stored object you can seek through, an email watcher that could stop listening without telling anyone now reports its health, and a search index that swallowed its own errors now says what failed.

Technology Teacher free October 4, 2026·6 min read·craft
TL;DR This post covers commits that landed on main during 2026-10-04 (UTC). Video import now stores one object and a ticketed range route can serve slices of it; the mail watcher reports when it stops listening and keeps unparseable mail; the search index writes atomically and reports failures on the health endpoint; the update snapshot no longer fails inside a transaction; and two small UI and query fixes landed. Several of these are first steps with stated gaps, listed at the end.

This post covers what landed on main on 2026-10-04 (UTC). It is a selection, not a changelog: roughly 380 commits landed that day, most of them tests, review fixes and bookkeeping, and we picked the changes a reader can learn something from. Every claim below traces to a commit we read; the short hashes are in the text and in the sources list.

The common thread: several things that used to fail without telling anyone now tell someone.

A video as one object, and a way to seek through it

Some vocabulary first. NAOMS stores large files as blobs: content-addressed objects, meaning the name of the object is derived from its bytes, so the same bytes always have the same address. A range request is an ordinary HTTP feature where a client asks for bytes 1,000,000 to 2,000,000 of a file instead of the whole thing; it is how a video player seeks without downloading everything first.

Before this day, importing a video went through the general file path, which cut it into chunks (the commit that added the red test records chunks:41 for a test video). Commit 82910507757 adds photos.video_import: a video becomes one blob, plus a node (a record in the app's local graph of things) marked as a video, kept private. Its test fixture is a 40.2 MiB MPEG-4 file. The command-line importer routes videos that are not Live Photos to it.

Serving it is a second piece. f1d04cf400d adds an HTTP route that answers range requests, and 3fd8c0110c5 generalises it to a blob-stream route. Access is by ticket: a short-lived token that authorizes reading one object, so the route does not need to know who is asking. The follow-up d06e79e0c21 records the edge cases the first review found: a malformed range maps to an error code rather than a success status, a small request with no range gets an ordinary full response, and multiple or inverted ranges are ignored.

Two guards came out of the review. 0ebfa537bba makes video import refuse unsupported flags loudly instead of silently dropping them, and the flat-blob server refuses anything over 16 MiB before reading it, rather than loading the whole object into memory. Because a ticket in a URL is a credential, 84473b4090b and 605b89357bb scrub tickets out of log messages and out of the persisted warning index; the red test in the first one shows a stored message that had contained a ticket-bearing URL.

One more small honesty change belongs here. When a file cannot be fetched from another device, 68da84b0a90 changes the Files Browser's wording: offline now reads "Not yet available on this device", and the case where the adding device never shared the file's address now names that reason. e80532e042d makes the route refuse before touching the network in that case, with a typed reason instead of a generic miss.

Mail that is not silently lost

An IMAP mail watcher keeps a connection open and asks the server to announce new mail (the IDLE command), and it remembers a cursor: the last message number it has handled, so a restart resumes after it.

Commit 84b00f7cd67 fixes two ways that design could lose mail without a sound. First, a failed IDLE just stopped the watcher, a failed restart of the wait was swallowed, and a connection that ended mid-wait was never noticed. The watcher now emits health events (dropped, recovered, failed), re-arms with bounded backoff, and runs a catch-up check after recovery. Second, mail that the parser threw on, or that had no headers, was skipped while the cursor moved past it, so it was gone for good. Now a row marking the parse failure, with the raw bytes stored in a blob, is written before the cursor may move on, and if that write fails the whole run fails.

The commit also records a decision: it did not change the oldest-first order, because the cursor logic needs it and newest-first would permanently skip older mail on any limited run.

A search index that said "not available" when it meant "broken"

The graph keeps a full-text search index (SQLite FTS5) so you can search your own data. Its writes were "best effort", and 8d15a445a9d describes what that meant in practice: every database error was caught, logged at debug level as "FTS not available, skipping", and discarded, so a failed batch returned counts identical to a successful one. The measured error text was actually a datatype mismatch, a malformed write rather than a missing index. Worse, the delete and insert steps committed separately, so a failure in between left rows deleted with no replacement.

The fix wraps both steps in one transaction, so a failure leaves the index unchanged, reports failures with the operation and SQLite's own error text, and adds a counter on the health endpoint. 12c4f541fbe applies the same treatment to the per-row path, and renames the counter to cover both paths. The commit message is also careful about its wording: after a rollback the old entry is still searchable but stale, and it says so.

An update that could not snapshot the database

Before applying an app update, the daemon copies its database with SQLite's VACUUM INTO. 4e57f8f6188 records that in a running daemon every such attempt was refused with "cannot VACUUM from within a transaction". The snapshot code opened its own connection to stay outside the daemon's transaction, but a lower layer swapped any handle for the process-wide live one. The fix adds an option, used only by the snapshot, that skips the swap. The commit message notes it left the global rule alone on purpose, because other callers depend on it.

Two small ones

6a56e5d10b7: the docked AI chat panel restored its saved pixel height on page load, and the code that re-stretches it only ran on a window resize, which a page load never triggers. It could end up short or overflowing; the commit's test shows gaps of 100, -100 and 180 pixels at three window sizes, and zero after the one-line fix.

f481a732a00: in a memory query, "this year" meant the trailing 365 days (2025-10-04 as the lower bound) when it should mean the calendar year so far (2026-01-01).

What we did not verify

  • We read commit messages and diffs; we did not run any of this. Test results quoted in the messages are the authors' own.
  • The video work is a first stage. The commit messages record that the route's parity test had a known unrelated failure and that the maximum flat-blob preview size is a cap, not a streaming path. We did not check playback in a real player.
  • The search fix covers the batch and per-row write paths; we did not check other index writers, and the schema-setup path still deliberately swallows errors where FTS5 is absent, with a single warning.
  • The mail commit's own message reports 5 unrelated daemon tests failing at that point because of a stale test fixture; we did not investigate.
  • We have not measured how often any of these failures happened in real use.
  • Several other fixes landed that day in areas we left out of this post.
