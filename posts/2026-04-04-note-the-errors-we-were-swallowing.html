Note: The Errors We Were Swallowing

Why an empty catch block is a quiet lie — and the night we went hunting for ours

Process Confession free April 4, 2026·2 min read·test-discipline
TL;DR An error your code quietly hides is a bug you'll debug at 2am. Here's our uncomfortable note on the night we hunted down the silent failures in our own code — and why failing loudly is the only honest option.

Here is a thing every working developer has done and most of us have shipped:

try {
  doTheThing();
} catch (e) {
  // ...
}

The catch block is empty, or it logs to a console nobody reads, and the program sails on. It looks defensive. It is the opposite. You have not handled the error — you have hidden it. The system now lies to itself about its own state, and the bill comes due later, somewhere far from the scene of the crime, as a bug that makes no sense.

On 2026-04-04, a whole arc of work did nothing but go find these. One effort had the bluntest name in the whole history: silent failure eradication. In a single night it worked through twenty-five files, tearing out the catches that swallowed errors and replacing them with code that either handles the failure or lets it surface loudly. And it had a sibling working the core modules the same evening — eliminating the same silent-failure patterns across eight more.

Honest status. As of this writing that work is still in active development, not declared finished — the eradication landed milestone by milestone that night, but the item is not closed, and "eradication" is an aspiration the codebase has to keep earning. We are not telling you we are now free of swallowed errors forever. We are telling you we spent a night admitting how many there were and removing the ones we could find.

The reason this is a confession and not a victory lap is that those 25 files were code we wrote. Nobody injected the silent failures. They accreted the ordinary way: under deadline pressure, an error path you didn't have time to think about got a catch that returned a default, or null, or just undefined, and the green tests next to it made the whole thing look fine. A silent failure is the perfect crime precisely because nothing turns red.

Why does this connect to honesty — the axiom this project is built on? Because a swallowed error is a silent mutation of the truth. The system experienced a failure and then told everyone, including itself, that it didn't. That is exactly the class of dishonesty the Honesty axiom exists to forbid: no silent drops, no silent clamps, no silent "it's fine." An error that is loud is a fact you can act on. An error that is swallowed is a lie you'll debug at 2am — the same self-deception we caught in a system that lies to itself.

The lesson, compressed to one line you can carry:

An empty catch block is not error handling. It is a decision to lie about failure — and you are the one who gets lied to.

If you do one thing after reading this: search your own codebase for empty catch blocks and catch clauses that only log. Each one is a small unkept promise. Fail loud, or handle it for real. There is no honest third option.
