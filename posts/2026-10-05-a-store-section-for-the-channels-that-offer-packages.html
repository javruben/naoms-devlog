A store section for the channels that offer packages

The Packages store now lists the marketplace channels your hives hold, with the ones you have joined ahead of the rest, and a Join button where joining is allowed.

Product Teacher free October 5, 2026·4 min read·craft
TL;DR The Packages store has a new 'Marketplace channels' section at the bottom of its Discover page. It lists the channels, from the hives your device belongs to, that a steward has authorised as places packages are offered. Each row shows the channel's name, a Joined mark if you are in it, and a Join button only when joining is allowed for you. Channels you have joined come ahead of the rest, after the default if there is one. A failed read is shown as an error, not as an empty list. A 'Default' badge exists but no channel carries it in this build yet.

When you open the Packages store you see listings: what a package does, who made it, what it costs in permissions. What the listing does not tell you, until you install, is where it was offered. This post is about the first piece of an answer: the store now has a section that lists the places packages are offered from, and lets you join them.

Some words first

A hive is a group of people who share a record of what happened. A channel is a smaller shared space inside a hive, like a room in a house; people announce things to each other there. A package is an installable piece of software or policy. A steward is a person with authority over a channel or hive: they can decide how it is set up.

A marketplace channel is a channel that has been set aside as a place where packages are announced. A channel becomes one when a package adoption marks it that way, and the marking only counts if the adoption was signed by someone the channel recognises as a steward. (The code notes that this check is slightly generous: it can credit someone promoted to steward after they adopted.) That condition matters because anyone can write a claim; the store lists channels only where someone with the right authority made it.

What the new section shows

At the bottom of the store's Discover page there is now a Marketplace channels section. Each row is one channel and shows:

  • the channel's name;
  • a Joined mark, if you are already a member;
  • a Join button, only when joining is actually allowed for you right now;
  • a Default badge, for the one channel a build ships as its starting marketplace.

Three details are worth knowing, because each one is a deliberate choice recorded in the code.

Which channels appear. The list is the marketplace channels your device already holds, because your device normally keeps a copy of the channels of the hives it belongs to. A channel not yet fully loaded on your device is left out. A channel you have not joined appears only if it is public. A private channel you have not joined is left out entirely, because even showing its name would tell you it exists; so is one whose visibility the device cannot read. And a channel only appears if a steward authorised its marketplace marking, so a channel that claims to be a marketplace without a steward behind it is hidden rather than shown with a warning.

Join is the ordinary channel join. When the list loads, the daemon (the background program on your device that does the work) says for each channel whether you may join, using the same check the ordinary channel Join uses, and the store draws the button only when that answer is yes. Pressing it calls the existing join operation, and the section reloads afterwards. If the join is refused, the store says it was refused and why.

The name is somebody else's text. A channel's name is written by whoever created it, so the store treats it as plain text and does not let it decide the order or the Default badge. In particular, the Default badge is drawn only from the build's own pinned choice, not from a name. A channel called "NAOMS Marketplace" looks like any other channel. In this build no channel is pinned as the default yet, so no row carries the badge.

The order, and why the name is not part of it

Rows are sorted: the default channel first (when there is one), then channels you have joined, then the rest.

The last step of the sort uses a channel's chain id, a long identifier derived partly from the name its creator typed. The commit that added the "joined before unjoined" step explains the reason: a creator can try names until the identifier sorts early, so sorting by identifier alone would let an unjoined look-alike appear above channels you already belong to. Putting joined channels first means grinding the identifier cannot lift a stranger above your own channels. The sort never reads the name.

An error is not an empty list

If the store cannot read the channel list, it shows "Marketplace channels could not be read" followed by the reason, and adds that this is not an empty list. If it reads fine and there are none, it says "No marketplace channels on this device yet." Those are different statements and the section keeps them different.

What this does not do yet

  • It lists channels your device already holds. Finding marketplace channels beyond your own hives is a separate piece of work, as the code comments describe it.
  • No channel is the Default yet, so the badge is built but not shown.
  • There is no screenshot in this post. The capture we have shows a channel name that is not suitable to publish, and a clean one is still to come.

What we did not verify

  • We did not run the app or any test for this post. Behaviour is described from the source on main and from the commit messages.
  • We did not check the section on a phone.
  • The ebdb284479d merge also carried other work unrelated to this feature; we describe only the marketplace-channels commits.
